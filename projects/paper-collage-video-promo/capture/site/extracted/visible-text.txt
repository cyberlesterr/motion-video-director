[h1] Paper Collage Video Pipeline
[p] 一个配置驱动的本地纸片分层视频生产系统。人负责内容意图、审美选择和最终批准；Codex 与本地工具负责节奏故事板、素材组织、分层关键帧、视听 cue、旁白同步、渲染和技术验收。
[p] 项目协议已直接推进到 v4；v3 及更早项目不会自动迁移或回退。v4 用递归组合树、注册源家族、支撑/边界模式和组合证明，防止“人物站在船外”“树被水层淹没”这类单图都合格但关系错误的问题。插件发行包带一个 2 秒低电平测试音技术夹具
[code] starter-demo
[p] 当前公开稳定版本为
[code] 0.8.0
[p] 。新协议加入必需的节奏故事板、注册组合模式、本地关键帧、逐节拍视听 cue、人物/拓扑/机构/说明图语义契约、真实生成尝试账本，以及资产/组合双质量门；功能和协议仍可能在
[code] 1.0.0
[p] 前调整。
[h2] 完整演示
[a] 观看或下载唯一完整演示：《铁杵磨针》77.7 秒 1080p 纸片故事
[p] Release 页的旧演示用于展示上一代质量门、六幕时间线、景深运动、字幕、虚构旁白和技术验收能力，不代表当前 v4 数据合同；使用边界见
[a] ASSET_LICENSES.md
[h2] 从 GitHub 安装 Plugin
[p] 面向普通用户的推荐路径是安装 Codex Plugin，不需要手动 clone 本仓库。仓库包含机器可读的 marketplace、插件清单、Skill、工作区初始化器和轻量 Remotion 模板。
[p] 用户可以直接把 GitHub 地址交给 Codex：
[code] 请安装这个 Codex 插件并完成初始化验证：
https://github.com/cyberlesterr/paper-collage-video
[p] Codex 对应执行：
[pre] codex plugin marketplace add cyberlesterr/paper-collage-video
codex plugin add paper-collage-video@paper-collage-video
[p] 安装后新建一个 Codex 任务，再说：
[code] 用 $make-paper-collage-video 做一条约 30 秒的玄奘西行纸片分层视频。
[p] 首次调用会从插件自带模板创建独立、可写的 Remotion 工作区，安装依赖并运行环境诊断。项目、依赖和渲染结果不会写入 Codex 的插件缓存。用户可能仍需批准依赖下载、FFmpeg 安装或图片/语音提供方授权。
[p] 源码采用
[a] MIT License
[p] 。测试夹具、纸张纹理和其衍生媒体不采用 MIT，只能按
[a] ASSET_LICENSES.md
[p] 随仓库运行、测试和演示。

[h2] 最简单的用法
[p] 在 Codex 中直接说：
[code] 用 $make-paper-collage-video 做一条约 30 秒的玄奘西行纸片分层视频。
[p] Skill 的维护源位于
[code] skills/make-paper-collage-video/
[p] ，发行副本位于插件包中。它按当前阶段加载必要 reference。新项目先锁定逐幕节拍与证明时刻，再把故事板、概念、制作档位/素材预算和三类 provider 放进同一次确认；之后只在风格/虚构音色和预览节点停下来。正式成片在本地技术验收通过后即完成交付，只有真正上传、发送或发布时才请求一次外部操作授权。中断后用精简的

[h2] 人在流程中的位置
[p] 正常制作一条新视频时，人参与三个内容节点：
[li] 口述主题后，一次确认概念、节奏故事板、时长/幕数、
[code] draft|balanced|full-depth
[li] 制作档位、素材预算和文本/生图/虚构语音 provider。
[li] 确认一张风格样张、短试听和必要时的 3–5 秒动作证明。
[code] preview.mp4
[li] ，批准或用自然语言提出修改意见。
[p] 最终视频和验收报告由系统自动交付；本地完成不等于允许外部发布。
[p] 人不需要手写人物坐标、处理透明通道、计算旁白帧数、修改 React 或执行 FFmpeg。
[code] project.json
[p] 是 Codex 和工具维护的机器协议。
[p] 完整的人机边界和审批节点见

[li] Python 3.11+（只在处理色键素材表时需要）

[h2] 角色素材表处理
[p] 一条命令完成四宫格拆分、软蒙版、通用去色键溢色和透明 PNG 输出。色键可自动从边框采样，也可以显式指定；选用服装中没有的高饱和颜色，不必固定为绿色：
[pre] npm run assets:process-sheet -- \
  public/projects/my-project/assets/characters/source/scene-sheet-green.png \
  public/projects/my-project/assets/characters/source \
  public/projects/my-project/assets/characters/alpha \
  scene 4 \
  --columns=2 \
  --key-color=auto \
  --matte-erode=1 \
  --names=emperor,maid-left,maid-right,officials
[p] 底层脚本仍可独立使用：
[pre] python3 scripts/split_sheet.py INPUT OUTPUT_DIR PREFIX COUNT --columns 2
python3 scripts/remove_chroma_key.py --input KEY.png --out ALPHA.png --key-color=auto --matte-erode=1 --force
[h2] 项目协议
[p] 项目配置遵循
[a] schemas/project.schema.json
[p] 。核心结构包括：
[code] video
[li] ：宽高和帧率。
[code] quality
[li] ：强制质量门使用的最低素材分辨率比例。
[code] theme
[li] ：纸张、字幕、描边和前景颜色。
[code] voice
[li] ：虚构音色或后续可选的克隆音色元数据。
[code] audio
[li] ：旁白、背景音乐和必填 LUFS/true-peak 交付规格。
[code] scenes
[li] ：故事板蓝图、带断言的证明时刻、递归
[code] composition
[li] 树、本地 keyframe、旁白、逐节拍 cue、转场和字幕。
[p] 镜头时长不是人工填写的常量，而是：
[code] round(旁白开始秒数 × fps) + ceil(真实旁白秒数 × fps) + ceil(尾部留白秒数 × fps)
[p] 后一个镜头按该镜头显式声明的
[code] transition.durationSeconds
[p] 与前一个镜头交叠。项目作者只写秒数和归一化的节拍/关键帧位置；帧数由渲染器根据 fps 推导。v3 及更早字段不会被迁移或猜测。
[p] 生产状态遵循
[a] schemas/production.schema.json
[p] 。它是断点恢复协议，不是创意配置：记录
[code] stage
[p] 、审批、粗粒度生产批次、产物和追加式事件历史。默认路径用组合故事板/概念/provider 确认、风格确认和预览确认。不要直接改状态 JSON。
[code] project:resume
[p] 只输出当前阶段、制作档位、控制模式、下一命令、未完成批次和 handoff 决定。只有
[code] WAIT-HUMAN
[p] 可以作为正常暂停点；
[code] AUTO-CONTINUE
[p] 的真实阻塞必须报告确切错误和唯一必要的人为动作。
[code] project:validate
[p] 检查：
[li] 项目协议、slug、视频规格和唯一 id。
[li] 递归节点、注册画布、支撑槽位/接触区、环境边界/mask、旁白、音乐、音效和纸张纹理是否存在且一致。
[li] 人物 PNG 是否真的有透明区域。
[li] 按透明像素推断真实色键，检查可见半透明边缘是否仍有对应溢色。
[li] 非注册场景素材是否达到输出规格；注册成员和 mask 是否与母版画布完全一致。
[li] 旁白配置时长是否等于 ffprobe 实测时长。
[li] 项目逐幕蓝图、组合模式、证明 id/时刻/断言是否与已批准故事板一致。
[li] 组与子节点关键帧是否覆盖完整镜头，每个故事节拍是否有唯一 cue、有效目标及正确证明窗口。
[li] 字幕范围、重叠、越界、单条长度和阅读速度。
[li] 支撑主体在各证明时刻是否仍位于接触区，注册环境是否只声明一次语义区域。
[code] project:quality
[p] 同时检查单文件和跨文件组合；文件哈希变化使资产审查失效，成员、mask、变换、边界、cue 或证明变化使对应组合审查失效。
[code] project:report
[p] 继续检查成片编码、分辨率、帧率、音轨、响度/峰值，并纳入 cue 事件表和真实组合证明摘要。
